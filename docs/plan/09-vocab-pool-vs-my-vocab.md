# 09 — 전체 단어장 / 나만의 단어장 분리 플랜 (2026-08-31)

사용자 요청: "오늘의 단어는 생성되면 기본적으로 전체 단어장으로 등록되는 거 아냐?" →
"전체 단어장 / 나만의 단어장 두 개의 관리 포인트를 나누자."

지금 UI 의 "전체 단어장" 메뉴는 이름과 달리 **내 카드 목록**(user_vocab_cards)이다.
AI 가 만드는 단어(퀴즈 10개·유의어/반의어·단어 세트)는 사용자가 버튼을 눌러야만 어딘가에 남고,
누르지 않으면 퀴즈 행(jsonb) 속에만 존재한다. 이 플랜은 두 관리 포인트를 분리해
"생성물은 자동으로 풀(전체 단어장)에 쌓이고, 학습(SRS)은 내가 고른 것(나만의 단어장)만" 구조로 만든다.

## 1. 현재 모델 — 분리에 유리한 상태

| 층 | 테이블 | 지금 역할 |
|---|---|---|
| 사전(풀) | `vocab_words` (word_key UNIQUE, source seed\|ai\|manual\|lesson\|conversation, created_by) | 이미 전역 사전이다. 시드 + 사용자가 추가한 단어가 쌓임 |
| 내 학습 | `user_vocab_cards` (user_id×word_id UNIQUE, SRS due/interval/status) | '오늘의 복습'과 UI 목록의 실제 소스 |
| 생성 이력 | `vocab_quizzes.words`(jsonb) · `vocab_sets.words`(jsonb) | 카드로 추가하기 전에는 여기에만 존재 |

즉 **DB 는 이미 2층 구조**고, 부족한 것은 ① 생성물이 `vocab_words` 로 자동 유입되지 않는 것,
② `vocab_words` 풀을 탐색하는 화면/API 가 없는 것, ③ UI 용어가 두 개념을 구분하지 않는 것.

## 2. 설계 결정

1. **용어 정리** — "전체 단어장" = `vocab_words` 풀(모든 출처의 사전 항목, 읽기 전용 탐색 + 담기). "나만의 단어장" = `user_vocab_cards`(SRS 학습 대상). 기존 UI 메뉴 "전체 단어장"은 "나만의 단어장"으로 개명하고, 새 "전체 단어장" 메뉴를 추가한다.
2. **AI 생성물은 전체 단어장에 자동 등록** — 퀴즈 생성(10단어), 유의어/반의어, 단어 세트 생성 시 `vocab_words` 에 upsert(이미 있으면 무시). **나만의 단어장에는 자동 추가하지 않는다** — 학습 부채를 사용자 동의 없이 늘리지 않는 것이 SRS 원칙(오늘의 복습이 갑자기 수십 개가 되는 것 방지).
3. **담기 흐름 통일** — 퀴즈 결과의 "틀린 단어/전부 추가", 관계어 [+], 단어 세트 "20단어 담기", 새 "전체 단어장" 화면의 [+] 모두 같은 의미: "풀 → 나만의 단어장으로 담기"(`user_vocab_cards` insert). 문구를 "단어장에 추가" → **"내 단어장에 담기"** 로 통일.
4. **퀴즈 제외 목록의 기준은 나만의 단어장 유지** — 출제 제외는 "내가 학습 중인 단어"가 기준(풀 전체를 제외하면 금방 소재 고갈). 단, 풀에 이미 있는 단어가 출제되면 뜻·예문은 **풀의 기존 항목을 재사용**해 사전 정보의 단일 소스를 지킨다.
5. **통계 분리** — 대시보드/통계의 단어 수치는 나만의 단어장 기준 유지. 전체 단어장 화면에만 풀 크기·출처별 집계(seed/ai/manual)를 보여준다.
6. **스키마 변경 최소** — 새 테이블 없음. `vocab_words` 에 이미 있는 `source`·`created_by` 로 출처 표시. 필요 시 후속으로 `vocab_words.etymology/synonyms/antonyms`(jsonb) 컬럼을 검토(퀴즈가 만든 어원·관계어를 풀에 보존 — 지금은 퀴즈 행에만 있음, §5 열린 질문 2).

## 3. Phase 플랜

### Phase 1 (2~3일) — 자동 유입 + 용어 정리
| 산출물 | 세부 |
|---|---|
| 자동 등록 | `createQuiz` 성공 직후 10단어를 `vocab_words` 에 upsert(예문·IPA·품사·난도 포함, `source='ai'`). `saveGeneratedVocabSet` 도 동일(현재는 세트 jsonb 에만 존재). 관계어는 [+] 클릭 시 upsert(현행 유지 — 뜻이 간단해 자동 등록 가치 낮음) |
| UI 개명 | 보조 사이드바 "전체 단어장" → "나만의 단어장", 카운트는 카드 수. 결과 화면 문구 "단어장에 추가" → "내 단어장에 담기" |
| API | 변경 없음(추가 흐름 재사용). `GET /api/vocab` 는 나만의 단어장 그대로 |

완료 판정: 퀴즈 생성 → 완료·추가 버튼 없이도 `vocab_words` 에 10행 존재(source='ai'), 나만의 단어장 카드 수는 불변. verify-quiz 에 단정 추가.

### Phase 2 (3~4일) — 전체 단어장 탐색 화면
| 산출물 | 세부 |
|---|---|
| `GET /api/vocab/pool?q=&source=&page=` | `vocab_words` 페이지네이션 검색(word_key ILIKE), 행에 `in_my_vocab`(내 카드 존재 여부) 포함 |
| 화면 | 단어장 탭에 "전체 단어장" 메뉴 신설: 검색창 + 출처 필터 칩(전체/시드/AI) + 행마다 [내 단어장에 담기]/[담김 ✓] + 발음(🔊) |
| 집계 | 헤더에 풀 크기·내가 담은 비율 (예: "428단어 · 내 단어장 132") |

완료 판정: 검색·필터·담기 멱등 E2E(e2e-vocab 확장), 담기 후 나만의 단어장·오늘의 복습에 반영.

### Phase 3 (선택) — 풀 품질 관리
- 어원·관계어를 `vocab_words` 로 승격(컬럼 추가 마이그레이션) — 퀴즈·전체 단어장·플래시카드가 같은 데이터를 봄.
- 중복 표기 정리(word_key 기준 대소문자·공백), AI 생성 항목 신고/수정.

## 4. 구현자 메모
- upsert 는 기존 `addCardFromEntry` 의 `vocab_words` insert 부분만 재사용(카드 insert 는 건너뜀) — 함수 분리(`upsertWordEntry`) 후 두 호출자가 공유.
- 퀴즈 자동 등록은 **createQuiz 트랜잭션 밖**(AI 호출과 같은 라우트 레벨)에서 — 실패해도 퀴즈 생성은 성공해야 한다(로그만).
- `in_my_vocab` 는 LEFT JOIN user_vocab_cards 파생 — 저장 금지 규범.
- e2e-vocab 의 "+added" 단정은 자동 등록 후에도 유효(카드 수 기준). 풀 단정은 pool API 로 별도.

## 5. 열린 질문
1. 다른 사용자가 만든 AI 단어(풀의 `created_by` 타인)를 전체 단어장에서 보여줄지 — v1은 전부 공개(사전 항목은 민감정보 아님), 문제 생기면 source 필터로 대응.
2. 어원·유의어·반의어를 풀로 승격할지(Phase 3) — 컬럼 추가 vs 퀴즈 행 참조 유지.
3. 레슨 지문 단어 칩("단어" 버튼)도 풀 자동 등록에 포함할지.
