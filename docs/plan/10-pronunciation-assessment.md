# 10 — 발음 평가 방식 비교 (2026-09-01)

플랜 08 Phase C 가 후속으로 미뤄둔 "발음 평가 API" 선택을 위한 비교.
현재 스피킹 화면은 **브라우저 STT + 단어 매칭**으로 동작하고, 화면에 나오는 수치는
'발음 점수'가 아니라 **'일치율'** 이다(의도적 표현 — §1 참조).

## 0. 결론 먼저

| 단계 | 선택 | 이유 |
|---|---|---|
| 지금(무료·프로토타입) | **브라우저 STT 유지** | 비용 0, 이미 동작. 단 '일치율'이라는 이름을 지킨다 |
| 유료 기능 출시 시 | **Speechace(또는 Azure) 도입** | 음소 단위 점수 + 캘리브레이션을 **사서** 쓴다. 자체 구현보다 압도적으로 빠름 |
| 대규모/온프레미스 필요 시 | 자체 GOP | 요청당 과금이 인프라비를 넘어서거나, 음성 외부 전송이 막힐 때만 |

**핵심**: 세 방식은 정확도 차이가 아니라 **측정 대상 자체가 다르다.**
브라우저 STT는 "무슨 단어로 들렸나", Speechace/GOP는 "그 소리가 목표 음소에 얼마나 가까운가"를 잰다.

## 1. 지금 구현이 실제로 재는 것

`src/screens/speaking.jsx` 의 `matchWords()` — 목표 문장과 인식 결과를 LCS 로 정렬해
단어별로 일치/치환/누락 3색을 칠하고 일치율 %를 낸다.

이건 **발음 점수가 아니다.** 브라우저 STT(내부적으로 강한 언어모델 보정)가
`vendor` 를 어색하게 읽어도 문맥으로 `vendor` 라고 적어주면 100% 가 나온다.
반대로 발음이 멀쩡해도 잡음·마이크 문제로 단어가 통째로 날아가면 0점이 된다.

→ 그래서 UI 문구를 "일치율"로 두고, 점수보다 **교정 힌트**를 크게 배치했다.
이 표현은 유료 평가를 붙이기 전까지 바꾸지 않는다.

## 2. 비교표

| 항목 | 브라우저 STT (현재) | Speechace | 자체 GOP |
|---|---|---|---|
| **측정 단위** | 단어(전사 일치 여부) | 음소·음절·단어·문장 | 음소(설계하기 나름) |
| **진단력** | "다른 단어로 들림"까지 | "θ를 s로 발음", 강세·유창성 | 음소 이탈도(라벨링 품질에 좌우) |
| **점수 신뢰도** | 캘리브레이션 없음 | 사람 채점 기준으로 튜닝됨 | **직접 캘리브레이션해야 함** |
| **비용** | 0 | 요청 단위 과금(단가는 계약 확인 필요) | GPU 인스턴스 + 개발·튜닝 공수 |
| **지연** | 즉시(스트리밍, 중간 결과 있음) | 녹음 종료 후 왕복(수백 ms~수 초) | 모델·하드웨어에 따라 큼 |
| **브라우저 커버리지** | **Chrome/Edge/Safari만.** Firefox 기본 미지원 | 전부(오디오만 올리면 됨) | 전부 |
| **음성 전송** | Chrome/Edge → Google, Safari → Apple 서버 | Speechace 서버 | 자체 서버(외부 전송 0) |
| **오프라인/온프레미스** | 불가 | 불가 | 가능 |
| **구현 공수** | 완료 | 며칠(녹음 업로드 + 응답 매핑) | 수 주(정렬·GOP·캘리브레이션·운영) |
| **HANDOFF §7 `word_scores` 충족** | ✗ | ○ (거의 그대로) | ○ (직접 만들어야) |

## 3. 각 방식의 실체

### 3.1 브라우저 STT (Web Speech `SpeechRecognition`)
- **장점**: 비용 0, 설치 0, 중간 결과가 실시간으로 나와 UX 가 즉각적이다.
- **함정 1 — 커버리지**: Firefox 는 기본 미지원. 데스크탑 우선 정책(`mobile:false`)과 겹쳐
  실사용 브라우저를 좁힌다. 지금 화면은 미지원/권한 거부를 구분해 안내하고 있다.
- **함정 2 — 언어모델 보정**: 정확한 발음을 요구하는 평가에는 구조적으로 부적합하다.
  "알아들었다"와 "잘 발음했다"가 다르다.
- **함정 3 — 프라이버시**: 무료지만 음성은 브라우저 벤더 서버로 나간다. 유료 서비스로
  갈 때 개인정보 처리방침에 반드시 명시해야 한다.

### 3.2 Speechace (상용 발음 평가 API)
- 음소·음절·단어별 점수와 유창성, 시험 점수 예측(IELTS/TOEFL/PTE 류)을 준다.
  영어 학습 앱을 위해 만들어진 서비스라 **피드백 문구까지 바로 쓸 수 있는 모양**으로 나온다.
- HANDOFF §7 이 이미 정의해둔 `word_scores: [{word, score}]` + `wordColor()` 색상 매핑에
  거의 그대로 대응된다 — 화면을 새로 설계할 필요가 없다.
- **가격은 공개 표준가가 아니라 계약 조건에 따르므로 반드시 직접 확인할 것.**
  이 문서에 단가를 적어두지 않는다(추정치를 사실처럼 굳히지 않기 위해).
- 대안: **Azure Speech Pronunciation Assessment** — accuracy/fluency/completeness/prosody +
  음소 단위 점수. 이미 Azure 를 쓰는 조직이면 조달이 더 쉽다. 기능 축은 Speechace 와 유사.

### 3.3 자체 GOP 구현
파이프라인:
1. **목표 음소열 생성** — 문장 → G2P(CMUdict / espeak-ng)로 기대 음소 시퀀스.
2. **강제 정렬(forced alignment)** — 음성과 목표 음소를 시간축에 맞춘다(MFA, Kaldi, 또는
   wav2vec2 CTC 기반 정렬).
3. **GOP 점수** — 각 구간에서 *목표 음소의 사후확률* vs *최고 확률 음소*를 비교해
   "얼마나 그 음소답게 소리 났나"를 수치화한다.
4. **캘리브레이션** — GOP 원값은 사람이 매긴 점수와 스케일이 다르다. 사람 채점 데이터로
   회귀/보정해야 "58점"이 의미를 가진다. 공개 데이터셋 **speechocean762**(L2 영어,
   음소·단어·문장 단위 사람 점수)가 사실상 표준 출발점이다.

- **진짜 비용은 GPU 가 아니라 4번**이다. 1~3번은 오픈 모델로 며칠이면 붙지만,
  캘리브레이션 없이 내보내면 "왜 이 점수인지 설명 못 하는 숫자"가 되고 학습자 신뢰를 잃는다.
- 얻는 것: 요청당 과금 0, 음성 외부 전송 0, 점수 기준을 우리가 정의할 수 있음.

## 4. 이 앱 기준 권고

1. **지금은 바꾸지 않는다.** 무저장 연습 모드에 브라우저 STT + 일치율이면 충분하고,
   유료화 전에 발음 점수를 붙이면 비용만 나간다.
2. **유료 기능을 열 때 Speechace/Azure 중 하나를 붙인다.** 이때 필요한 서버 작업은
   이미 HANDOFF §7 에 설계돼 있다 — MediaRecorder 로 오디오 캡처 → 서버 업로드 →
   평가 API 호출 → `word_scores` 로 매핑. **화면은 색상 매핑만 재사용하면 된다.**
3. **자체 GOP 는 트리거가 생기면 착수한다.** 트리거는 둘 중 하나:
   - 월 평가 요청량 × 단가 > GPU 인스턴스 + 유지보수 비용
   - 음성 외부 전송이 계약·규정상 불가(B2B·교육기관 납품 등)
4. **어느 쪽을 붙이든 '일치율'과 '발음 점수'는 화면에서 구분해 표시한다.**
   같은 숫자처럼 보이면 사용자가 무료 티어의 일치율을 발음 점수로 오해한다.

## 5. HANDOFF 문서와의 불일치 (이 문서로 정정)

- §6 비용표는 음성 인식을 **Whisper**로 잡아뒀는데, §7 은 **단어별 발음 점수**를 전제한다.
  Whisper 는 전사(ASR) 모델이라 `word_scores` 를 만들지 못한다 — 악센트에 강건하도록
  설계돼 있어 오히려 발음 오류를 지운다.
- 정정: **Whisper 는 리스닝 받아쓰기·자유 회화 서버 STT 용도**로 남기고,
  발음 평가는 별도 항목(Speechace/Azure 또는 자체 GOP)으로 잡는다.

## 6. 열린 질문

1. 무료 티어에 발음 점수를 일부라도 줄지 — 준다면 일 N회 제한이 필요하다.
2. 평가 이력을 저장할지(현재 v1 무저장). 저장하면 점수 추이·약점 음소 집계가 가능해지지만
   음성 원본 보관 여부·기간을 개인정보 처리방침에 명시해야 한다.
3. 한국인 학습자 특화 약점(θ/ð, r/l, f/p, 최종 자음군)을 별도 리포트로 뽑을지 —
   음소 단위 점수가 있어야 가능하므로 2번 단계 이후.
