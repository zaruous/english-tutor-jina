# docs/reviews/ — 외부 에이전트 위임 기록

Cursor·Codex 등에게 설계·구현·리뷰를 맡긴 **라운드**를 순서대로 남긴다.
목적은 결과물 보관이 아니라 **"누구에게 무엇을 어떻게 시켰고, 그게 맞았는지"** 를 다음 라운드가 참조하는 것이다.

## 이름 규칙

```
NN-YYYY-MM-DD-<에이전트>-<주제>[/]
```

- `NN` — **라운드 번호**. 날짜만으로는 같은 날 두 건의 순서를 알 수 없고 몇 번째인지도 안 보인다.
- `<에이전트>` — 누가 대상인지가 폴더 이름에서 바로 보여야 한다. 여럿이면 `trio-cursor+codex` 처럼 이어 쓴다.
- 산출물이 파일 하나면 `.md`, 여러 개면 디렉터리.

## 라운드 디렉터리 안쪽

| 파일 | 내용 |
|---|---|
| `01-task-prompt.md` | 에이전트에게 준 **지시서 원문** (`coworks/prompts/` 사본) |
| `02-agent-report.md` | 에이전트의 **자체 보고 원문** (`coworks/logs/` 사본) |
| `03-verification.md` | 우리가 **직접 재실행해 검증**한 결과. 자체 보고를 인용하지 않는다 |
| `04-grade.md` | [채점표](rubric-delegated-implementation.md) 기준 점수 |
| `05-fixes.md` | 조치한 것 · 남긴 것 · **우리 지적이 틀렸던 것** |
| `img/` | 스크린샷 등 산출물. 목업 전용인 `docs/plan/img/` 와 섞지 않는다 |

지시서와 에이전트 원문을 **저장소 안에 복사해 둔다.** `coworks/` 는 이 저장소 밖이라
거기에만 두면 "무엇을 시켰는지" 가 남지 않고, 결과만 보고 판단하게 된다.

## 규칙

- **자체 보고를 검증으로 삼지 않는다.** `03-verification.md` 는 명령을 직접 돌린 결과만 적는다.
- **채점표의 ★ 항목(검증 신뢰성·보고 정직성)은 위임자가 채점하지 않는다.** 자기 테스트가 믿을 만한지,
  자기 보고가 정직한지는 자기가 판정할 수 없다.
- **우리가 틀린 것도 적는다.** 03회차에서 "행이 잘렸다" 는 지적이 내부 스크롤을 스크린샷이
  못 담은 것이었다(`05-fixes.md` §3). 오판 기록이 다음 라운드의 판단 기준이 된다.
