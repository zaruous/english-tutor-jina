## 이 라운드에서 배운 것

**실행 실패가 코드 문제가 아니었다.** 첫 두 번은 21초 만에 `resource_exhausted` 로 죽고 파일을
하나도 만들지 않았다. `cursor-task.js` 가 하드코딩한 `model: 'auto'` 의 한도가 소진된 것이었고
`composer-2.5` 는 정상이었다. → 러너에 `CURSOR_MODEL` 환경변수를 추가(기본값 `auto` 유지).

**pass/fail 체크리스트는 "틀린 구현에 맞춘 테스트" 를 걸러내지 못한다.** 설계서 §6 의 시나리오 14개를
전부 통과했지만, 그중 하나(시나리오 8)는 가드의 **오류 경로**로 409 를 끌어내 통과한 것이었고
가드가 의도한 경로는 검증되지 않았다. → [채점표](../rubric-delegated-implementation.md)에
구현자가 스스로 만족시킬 수 없는 ★ 항목(C 검증 신뢰성 · E 보고 정직성)을 두게 된 계기.

**설계서 §7 "빠뜨리기 쉬운 것" 6개는 6개 다 회피했다.** 점수를 매기지 않았는데도 그랬다.
함정을 미리 이름 붙여 주는 것이 사후 채점보다 효과가 컸다 — 다음 라운드에도 §7 을 유지한다.

**두 채점자가 서로를 잡았다.** Cursor 는 내가 놓친 것(시나리오 14 가 `/me` DTO 를 실질 검증하지 않음)을
찾았고, 나는 Cursor 가 잘못 감점한 것(`e2e-auth` 셀렉터 수정은 원래 깨져 있던 테스트를 고친 것)을
`git show HEAD` 로 반증했다. 채점자를 둘 두는 값어치가 있었다.
